# Sample Reports — Decision & Format

The brief asks for "≥2 sample reports generated by the system." This project's system is a conversational chatbot so our conversational and error logs are taken as the output.

## The two samples

The system produces two structured outputs: a `chat_log` and an `error_log`. One sample covers each.

- `sample_report_1.md` — a real `chat_log` session (20 turns). Covers work history retrieval, LinkedIn, sending a message, and a full Calendly booking including a failed attempt and a successful retry. Includes a raw-table excerpt at the top showing the five-column log structure, then the full readable conversation.
- `sample_report_2.md` — the full `error_log` export (9 rows, 4 columns). Shows all three error capture mechanisms in action across real test executions: logging node error output, RAG Agent hard crashes, and `Listen for Silent Errors` (tool failures absorbed by the agent).

**Note:** Personal email addresses and the Calendly username are redacted. Nothing else has been changed.
